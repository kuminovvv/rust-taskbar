# Архитектурная гипотеза (подлежит проверке в PoC)

## Технологии

- Rust stable, `windows`/`windows-sys` (windows-rs) для Win32 и COM.
- Окна: нативный Win32, per-monitor DPI awareness v2.
- Композиция: проверить **Windows.UI.Composition** и **DirectComposition** с учётом рекомендаций Microsoft; Direct2D для текста/иконок и GPU-ресурсов.
- Конфиг: локальный TOML/JSON, атомарная запись; не лезть в конфигурацию штатной панели.
- Логи: только локальная диагностика, без захвата содержимого окон или пользовательских файлов.

## Модель событий

1. Начальная инвентаризация видимых top-level окон (например, `EnumWindows`).
2. Реакция на Shell hooks/WinEventHooks/Win32 messages с дебаунсом и периодической проверкой целостности **только если действительно нужно**.
3. Актуализация модели окон отдельно от UI; кэш иконок, минимизация COM/Win32 вызовов с UI-потока.
4. Изменение модели => точечный update UI tree; не перерисовывать всё без повода.
5. Для анимаций использовать композитор, задавая time-based transitions; при отсутствии изменений UI не крутит собственный цикл 180 FPS.

## 180 Гц

- Один период при 180 Гц = 5,56 мс. Это frame pacing requirement, а не время, которое обязательно тратит CPU.
- Проверять на реальном мониторе 180 Гц или выше, через PresentMon/ETW/WPA; контролировать пропуски кадров и задержку ввода.
- Задействовать `prefers-reduced-motion`-эквивалент Windows (system UI animation settings), обрабатывать энергосбережение/RDP и низкую частоту монитора.
- Измерять на 60/120/144/180 Гц, отдельно в простое, при hover, запуске приложений, видеозвонке и игре.

## Ориентиры (не измерения)

- Процесс панели: до 40 МБ private working set после прогрева (ориентир, может измениться после PoC).
- Idle CPU: <= 0,2% одного логического CPU при типовой загрузке системы без событий; GPU idle практически нулевой.
- Отзывчивость: no dropped frames в целевом 180 Гц тесте простых transform/opacity анимаций; 99-й перцентиль frame interval <= 5,56 мс на стабильной тестовой системе — амбициозная цель, проверять фактически.
- Ограничения: FPS на частоте дисплея, составные DWM кадры, неодинаковые refresh rates и экономия энергии.
- Цифры могут зависеть от CPU/GPU, режима питания, сборки Windows, устройства/драйверов и числа мониторов.

## Риски совместимости (spikes до реализации)

- **System tray**: сторонние приложения регистрируют иконки через `Shell_NotifyIcon`, но это API для взаимодействия с системной областью уведомлений, а не гарантированный публичный способ получать полный перечень и обратные вызовы в отдельной панели. Нельзя закладывать P0 «полный трей» без работающего эксперимента.
- **Taskbar integrations**: программы используют `ITaskbarList3` (progress, overlays, thumbnail buttons); не assume that a third-party dock automatically observes these signals.
- **App grouping**: группировка по исполняемому файлу недостаточна; учитывать AppUserModelID, UWP и окна-посредники.
- **Virtual desktops**: официальные интерфейсы покрывают часть сценариев; не завязываться на неподдерживаемые COM-интерфейсы.
- **AppBar**: `SHAppBarMessage` позволяет резервировать место, но совместное существование двух панелей, auto-hide и несколько дисплеев требуют тестов.
- **Explorer**: начальные версии не останавливают его, не заменяют shell и не меняют системные DLL.

## Принципы безопасной разработки

- Никаких инъекций кода и глобальных хуков в другие процессы без отдельного разбора.
- Падение / обновление / закрытие не должно оставлять пользователя без доступной панели или меню «Пуск».
- Вся продуктивность измеряется воспроизводимыми бенчмарками; запрещены неподтверждённые заявления «180 FPS» и «0% CPU».
